Phase 27 Continued: Designer JS Bug Fix & Canvas API Compatibility (2026-05-11)
================================================================================

Overview:
After deploying the Fabric.js designer, all toolbar buttons (text, shapes, images, templates, etc.) were non-functional — clicking them did nothing. The root cause was a JavaScript TypeError from canvas.undo() which doesn't exist in Fabric.js 5.x, cascading to break ALL event handler bindings. Fixed all Fabric.js v5 API incompatibilities and implemented a proper undo/redo history system.

Tasks Completed ✅

1. Root Cause Diagnosis:
   - The original designer.js called canvas.undo() and canvas.redo() which are NOT native Fabric.js methods — they do not exist in any Fabric.js version
   - This threw an uncaught JavaScript TypeError at page load, preventing ALL subsequent event handler bindings from executing
   - Also found: stateful: true is an invalid canvas option in Fabric.js 5.x and was silently ignored but contributed to instability
   - The copy/paste system used fabric.loadFromJSON() incorrectly for single-object cloning instead of fabric.util.enlivenObjects()
   - Group/ungroup operations did not properly handle object lifecycle (removing individual objects before grouping)

2. Complete designer.js Rewrite (public/js/designer.js):
   - Removed invalid canvas options (stateful: true)
   - Implemented custom undo/redo history system using a state stack (historyStack array, historyIndex tracker)
   - saveState(): stores JSON.stringify(canvas.toJSON(['id'])), maintains max 100 entries, truncates future on new action
   - undo()/redo(): uses canvas.loadFromJSON()+callback with isRestoring flag to prevent re-triggering state saves
   - Fixed copy: uses obj.clone() callback pattern instead of JSON.stringify(obj.toJSON())
   - Fixed paste: uses fabric.util.enlivenObjects([json], callback) instead of fabric.loadFromJSON()
   - Fixed group: properly discards active selection, removes objects from canvas, then adds group
   - Fixed ungroup: destroys group, re-adds all _objects individually to canvas
   - Fixed image upload: constrains both width AND height to max 200px
   - Fixed zoom: proper min 0.3 / max 3 bounds enforcement
   - Fixed right panel switching: shows correct panel for text, image, shape objects
   - Added canvas:object:modified event binding for automatic state save
   - Added CSRF token validation in orderDesign() function with user-facing alert on failure

3. View Fix (designer/index.blade.php):
   - Added missing <meta name="csrf-token" content="{{ csrf_token() }}"> to <head>
   - Without this, the "下单" button would show "CSRF token missing" alert
